Claude Code **v2.1.271**, released September 14, is a large operational release for teams running Claude Code beyond a single local terminal. It expands fast mode into Remote sessions, tightens sandbox egress around individual commands, adds safer plugin-install automation, and hardens managed-policy, MCP, resume, and self-hosted-runner behavior. **v2.1.272**, released September 15, contains only the official note “Bug fixes and reliability improvements,” so there is no narrower claim to make about that patch yet.

## What matters most

- **Fast mode now follows Remote sessions.** The v2.1.271 release notes say fast mode works in Claude Code Remote sessions, including cloud and self-hosted runners, subject to organization policy. The existing `/fast [on|off]` command remains the control surface documented in the Commands reference.
- **Sandbox network access can be scoped per command.** Bash, PowerShell, and Monitor calls running in auto mode with sandboxing can now carry `allowed_domains`. The release notes describe those hosts as being reviewed with the command and opened only for that command, while other hosts remain refused. This is a useful direction for CI and agent runners because it reduces the need for broad session-level egress exceptions.
- **Self-hosted runners get better drain semantics.** `claude self-hosted-runner --drain-marker-file <path>` lets an operator mark a SIGTERM drain as a host drain for telemetry. The same release also adds `--host-config-snapshot disk|memory` to address cases where a large host configuration could disappear from a self-hosted session.
- **Plugin command approval becomes hash-specific.** `claude plugin install` and `claude plugin update` can use `--accept-command <sha256>` to accept exactly the command shown by a previous JSON run instead of using a broad `-y`. That gives automation a narrower approval primitive when a marketplace operation needs to execute a command.
- **Custom agents can opt out of regular CLAUDE.md context.** The new `omitClaudeMd` field in agent frontmatter and `--agents` JSON lets custom and plugin subagents skip user, project, and local CLAUDE.md files while still loading managed policy files. This can reduce accidental context inheritance for narrowly scoped agents.

## Enterprise and security fixes

The release repairs several policy-boundary issues worth testing in managed environments. Cached organization policy is no longer supposed to survive an account, organization, or API-key switch incorrectly, and tool/command lists are refreshed when policy arrives or changes after startup. An unreadable or malformed enterprise `managed-mcp.json` now retains exclusive MCP control and warns instead of silently falling back to user, project, or plugin MCP servers.

Bash permission checking also received multiple fixes: files hidden behind unfamiliar options or wildcard expansion are handled more carefully, shell-variable declaration flags can no longer misrepresent the command being checked, and chained directory changes or `cd` plus `git` flows no longer skip prompts under `permissions.blockReadsOutsideWorkingDirectories` in bypass and auto modes.

For long-lived sessions, Anthropic also fixed duplicated background commands after compaction, stale file-read tracking after `/resume` and `/teleport`, dropped 1M-context state on some resumed sessions, repeated MCP list-change CPU churn, and several Remote Control and OAuth edge cases.

## What is not in the cheatsheet yet

This release introduces several new interfaces in release notes, but the current CLI, Commands, and Settings references do not yet independently document the exact new `--drain-marker-file`, `--accept-command`, `omitClaudeMd`, or `modelPricing` multiplier behavior. The cheatsheet therefore stays unchanged for now rather than treating release-note-only interfaces as fully matured reference documentation.

## Suggested rollout

For managed or CI-heavy environments, update a canary first and exercise the permission boundary you actually depend on: sandboxed network commands, managed MCP policy, plugin install/update automation, Remote sessions, and runner shutdown/drain behavior. If you use v2.1.271 in production, take v2.1.272 as the follow-up reliability patch, but do not infer fixes beyond Anthropic’s generic release note.
