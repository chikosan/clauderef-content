Claude Code **v2.1.289 through v2.1.316** turn the October release stream into a practical operations update. The series adds Haiku 5.5 support, idle compaction, an advisor workflow, better subagent controls, more capable plugin and mod APIs, stronger hook and sandbox boundaries, and clearer telemetry for permission decisions. It also changes several defaults in headless, cloud, and self-hosted sessions, so teams should test an upgrade rather than treat it as a collection of cosmetic fixes. There was no separate v2.1.315 release; the official release feed moves from v2.1.314 to v2.1.316.

## The biggest user-facing changes

### Long sessions can compact while you are away

Claude Code v2.1.299 adds idle compaction for terminal sessions: a conversation above the configured token threshold can be summarized while it sits idle, before the one-hour prompt cache expires. The `idleCompaction` setting can disable it, and `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` changes the threshold. v2.1.302 adds an `/config` row for the setting, while v2.1.314 extends the behavior to the Code tab in Claude Desktop and VS Code. This is useful for long-running work, but the summary is still a lossy boundary: inspect the next prompt when a paused session contains important context.

### Models and effort are easier to control

v2.1.293 makes **Claude Haiku 5.5** the default Haiku model on the Anthropic API; the official model documentation says to use Claude Code v2.1.293 or later for it. Earlier in the series, Sonnet 5.5 became available in v2.1.284, and the current model guide now lists all three 5.5 families with provider-specific availability. v2.1.292 adds an `effort` parameter to the Agent tool, v2.1.311 makes `ultrathink` map to xhigh effort for supported models, and v2.1.314 lowers effort and retries when an administrator caps the requested level. The result is more predictable policy behavior: a managed cap may change what runs, but the session now explains the level it actually used.

The new advisor path is also documented: `/advisor` or `--advisor <model>` lets a primary model consult a second model at key moments. Treat it as a deliberate cost and latency choice, not as a guarantee that every task will improve.

### Plugins, mods, and hooks gain real policy surfaces

Plugin operators get several practical improvements. `claude plugin install --marketplace <source>` can add a marketplace and install from it in one command, while `claude plugin validate` reports more configuration and hook safety information. v2.1.295 adds `onFailure: "block"` for command and HTTP hooks, so a hook that cannot start, times out, or exits unexpectedly can stop the action instead of silently allowing it. v2.1.289 and v2.1.292 expand mod events and agent hooks, including teammate identity, agent effort, prompt autocomplete, and workflow-agent controls.

These capabilities increase the value of policy plugins and also increase their blast radius. Review the plugin source, marketplace trust, managed-settings boundaries, and hook failure behavior before enabling a new mod across a team.

### Automation is more observable and less surprising

The release train makes headless and scheduled workflows easier to reason about. v2.1.292 changes local MCP connections to negotiate protocol version **2026-07-28** by default, with `MCP_PROTOCOL_NEGOTIATION=legacy` as the opt-out. v2.1.300 adds OpenTelemetry GenAI semantic-convention attributes, and v2.1.301 adds classifier and permission-mode fields to `tool_decision` events. v2.1.307 adds the `/claude-api api-version` command for API migrations and retries unparseable tool calls up to twice. v2.1.309 makes `sed -i` behave as a normal Bash edit and requires workspace trust for `claude ultrareview`.

For self-hosted environments, v2.1.311 adds `--hold-idle-file` and `--max-hold-min` so a runner can keep an idle session alive while host processes finish. v2.1.314 also improves memory use in long headless turns with many subagents. These changes favor explicit lifecycle signals over a process that happens to remain alive.

### Safety boundaries get clearer

v2.1.304 adds `/auto-mode-setup`, a guided way to teach auto mode about a repository and its trusted environment. v2.1.305 adds `sandbox.allowNestedUserNamespaces` for Linux and WSL2 workloads such as Chromium or rootless Podman, but the setting deliberately weakens part of the sandbox's file protection. v2.1.309 changes dangerous `rm` and `rmdir` behavior in bypass-permissions mode in Desktop and VS Code to deny the command with a rewrite hint. Finally, v2.1.314 adds managed `permissions.blockWritesOutsideWorkingDirectories`, which makes Write, Edit, and NotebookEdit refuse paths outside the working directories in every permission mode.

The practical takeaway is not to turn every safeguard off when a tool fails. Start with the narrowest allowlist or working-directory change, then document any exception in managed settings and test it in the same client surface your team uses.

### v2.1.316 adds effort controls and a fast-mode deadline

Claude Code v2.1.316 adds `CLAUDE_CODE_SUBAGENT_EFFORT`, which sets the effort level for subagents when no other setting names one. That gives teams a way to keep background work from silently inheriting the parent session's effort choice. The same release adds `CLAUDE_CODE_DISABLE_ULTRATHINK`, which turns off the `ultrathink` keyword when a workflow needs an explicit effort setting instead.

The release also deprecates fast mode for Opus 4.8 on October 30, 2026. Anthropic says it will be removed on November 30, 2026; after removal, fast-mode requests for Opus 4.8 will error rather than fall back to standard speed. Teams using that combination should move to Opus 5.5 for the speedup before the deadline. The other new v2.1.316 gateway controls—pooled group budgets, layered policy merging, and Bedrock guardrail input tagging—are administrator-facing Claude apps gateway settings, not general local CLI flags.

## What to do before upgrading

If you run Claude Code interactively, update and check the model table, then try idle compaction with a disposable long session. If you run plugins, validate them and test hook failures explicitly. If you run headless, cloud, or self-hosted sessions, verify MCP negotiation, subagent defaults, telemetry fields, runner drain behavior, and workspace trust. If you use Opus 4.8 fast mode, schedule the migration before November 30. Gateway operators should separately review the release notes for pooled budgets, layered policies, Bedrock input tagging, OIDC claims, per-group routing, guardrail tracing, model filters, and upstream timeouts; those are gateway configuration features, not universal local-CLI behavior.

claude update
