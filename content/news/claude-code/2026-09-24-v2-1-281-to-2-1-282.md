Claude Code **v2.1.281** and **v2.1.282**, released on September 23 and 24, are mostly operations and reliability updates. The useful theme is control: gateway operators get more policy and identity options, plugin authors get stronger validation, and long-running sessions recover more safely from interrupted or malformed history.

## Gateway controls become more practical

Claude apps gateway Bedrock upstreams can now use `assume_role`, including a role in another AWS account, and can apply an Amazon Bedrock guardrail with `guardrail: {id, version}`. Gateway telemetry can also receive fixed `telemetry.resource_attributes`, while newer Claude Desktop policy keys are accepted in `desktop` blocks. These are operator-facing additions: they help separate gateway identity from provider identity, apply a consistent safety policy, and label telemetry without changing ordinary terminal use.

Version 2.1.282 adds `store.readiness_grace_seconds`, which lets the gateway remain ready through a short Postgres outage such as a failover. It also fixes several gateway and provider edge cases, including clearer Bedrock block identifiers and better handling of responses interrupted by proxies.

## MCP and plugins fail earlier and explain more

MCP URL-mode elicitation is now supported for servers using the 2026-07-28 protocol. A server can ask Claude Code to open a browser-based flow, without leaving an on-screen waiting dialog when the server cannot confirm completion itself.

`claude plugin validate` now checks MCP configuration that could otherwise be silently discarded, undeclared `${user_config.*}` references, and insecure URLs. That makes it a useful pre-merge check for plugin repositories. The release also adds an `/insights` recommendation estimating how many recent permission prompts auto mode might have handled; it is guidance, not a new permission mode.

## Resuming and unattended work is more resilient

Many of the fixes target sessions that are resumed, proxied, scheduled, or run headlessly. Claude Code repairs more forms of changed conversation history, preserves more large-session context, avoids retry loops that could ignore `--max-turns`, and handles dropped or duplicated stream events without silently treating incomplete output as a complete answer. Host-side MCP handshakes in Agent SDK sessions now have a bounded wait, and scheduled `/loop` wakeups no longer repeat every second after a delivery failure.

The releases also improve safety boundaries. Recursive `rm` targets derived only from command substitution now require confirmation even when a Bash allow rule exists, unless the explicit compatibility override is set. Workspace trust is checked before `claude --bg` starts a background session or project hooks, and special macOS path forms are not read before approval. Managed settings, permission rules, null-byte paths, plugin uninstall, and credential refresh receive related correctness fixes.

Version 2.1.282 adds `maxProseWidth`, which caps Claude's prose width in wide terminals while leaving tables and code blocks full width. It also reports telemetry variables that were ignored in project settings, adds a managed setting for using Claude in Chrome with an exclusive managed MCP configuration, and fixes more resume, compaction, thinking, and provider-specific failures.

## What to do

Upgrade first if you operate a gateway, use Bedrock, rely on MCP or plugins, or run scheduled/headless sessions. Validate role assumption, guardrails, plugin configuration, resume behavior, and permission rules in a representative environment before a broad rollout.

```bash
claude update
claude --version
```

The compact cheatsheet now records the documented `maxProseWidth` setting. The other new gateway and plugin interfaces remain release- or configuration-reference details rather than compact reference entries.
