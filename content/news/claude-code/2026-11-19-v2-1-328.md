Claude Code **v2.1.328**, released November 19, broadens auto mode beyond the Anthropic API and tightens a few important automation boundaries. The release also adds clearer warnings for lost telemetry and cloud-message delivery, plus a set of Code Mode and self-hosted-runner fixes.

## Auto mode reaches more providers

Auto mode is now available for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud’s Agent Platform, Microsoft Foundry, and the Claude apps gateway. In interactive sessions that do not specify a permission mode, those models now start in auto mode. The release also changes plan-mode and Bash prompts on third-party providers to use and offer auto mode, unless `disableAutoMode` turns it off.

This is useful for teams that run Claude Code through a provider-specific gateway or cloud account rather than the Anthropic API. It is not a reason to remove permission rules: auto mode still needs a deliberate policy, trusted working directories, and a clear understanding of what the provider can enforce. Test the effective mode with `/status` and keep managed settings authoritative where policy requires it.

## MCP hook failures can block actions

The `mcp_tool` hook schema now accepts `onFailure: "block"`, matching command and HTTP hooks. A hook that fails can therefore block the associated action. This is a small configuration addition with a meaningful safety effect: validation, authorization, or audit hooks no longer have to choose between logging a failure and letting the tool call continue.

Use blocking hooks for checks that must succeed before an MCP action proceeds, and make the failure message actionable. A block is only useful if the hook is reliable, so test timeouts, malformed input, and the server-unavailable case before applying it to a shared configuration.

## More control over resumed tool calls

Hosts can set `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME` to stop `claude -p --resume` and `--continue` from running a tool call that a hook deferred. This gives wrapper scripts and controlled runners a way to require a fresh decision instead of replaying deferred work during session recovery. Treat the setting as a host policy: document it next to the hook that defers the action and verify the resulting exit behaviour in a disposable session.

Self-hosted runners also gain `--repository-folder` for stable repository names when capacity is one, `--hook-label` for passing chosen labels to the `spawn-runner` hook, and `--metadata key=value` for labeling a session started with `claude --environment`. These options make runner orchestration easier to inspect without relying on a repository’s full path.

## What to do

Upgrade a canary installation first. If you use a non-Anthropic provider, verify auto mode and the effective permission policy with `/status`. Add `onFailure: "block"` only to MCP hooks that are safe to fail closed, and test resumed sessions if your host uses deferred tool calls. Runner operators should record the new labels and repository-folder conventions in their launch configuration.
