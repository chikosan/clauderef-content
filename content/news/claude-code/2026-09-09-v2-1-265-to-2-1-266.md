Claude Code **v2.1.265–v2.1.266**, published September 8, 2026, is a release pair worth noticing if you operate Claude Code through internal gateways, shared plugin bundles, background agents, or long-running sessions. v2.1.265 adds a useful plugin-loading capability and a large set of reliability fixes. v2.1.266 then corrects an authentication regression introduced by 2.1.265 for some gateway and proxy configurations.

## The operationally important changes

- **A plugin directory can now contain multiple plugins.** `--plugin-dir` can point at a parent folder, and Claude Code loads each child folder that contains a plugin manifest. Children added or removed while the session is running are detected as well. This is useful for local plugin development, shared CI images, and teams that maintain a checked-out bundle of plugins instead of passing one flag per plugin.
- **Gateway and proxy users should prefer v2.1.266 over v2.1.265.** In 2.1.265, the undocumented `CLAUDE_CODE_USE_GATEWAY` environment variable started forcing Claude apps gateway sign-in by itself. Setups that also used an API key, `apiKeyHelper`, or custom auth headers could then fail every request with `Not signed in to the Cloud gateway`. v2.1.266 restores the previous behavior: that variable alone is ignored again, so no configuration change is required after upgrading.
- **Prompt-cache stability improved for resumed and multi-agent work.** v2.1.265 fixes resumed foreground subagents changing their tool list or system-prompt prefix, and fixes teammates or resumed subagents moving hook context and preloaded skills out of the prompt prefix on later turns. Both behaviors could cause unnecessary prompt-cache misses.
- **Interrupted sessions resume more safely.** If the previous process died while a tool was running, resume no longer rewrites the final prompt; the interrupted tool call is retained and marked as interrupted. Background sessions also receive fixes around idle retirement and Remote Control end-of-turn ordering.
- **Plugin handling is stricter.** v2.1.265 closes a plugin symlink-containment bypass involving backslashes on macOS and Linux, improves validation of plugin directories, and improves metadata shown for marketplace plugins.

## What this means for CI and platform teams

If your runners or developer workstations route Claude Code through an internal LLM gateway, **upgrade directly to v2.1.266 or later** rather than pinning 2.1.265. Also audit your environment for `CLAUDE_CODE_USE_GATEWAY`: it is explicitly described as undocumented in the release notes, so it should not be treated as a stable configuration contract.

For plugin development, the new folder behavior can simplify ephemeral test environments. A CI job can check out a curated plugin bundle and start Claude Code with one parent path instead of assembling many `--plugin-dir` arguments. Keep the bundle reviewable and immutable in production runners; hot discovery of newly added child plugins is convenient for development, but deterministic CI should still pin exactly what is present at job start.

The cache fixes are also relevant to cost and latency. Teams using resumed subagents, agent teammates, or long sessions should see fewer avoidable cache misses caused by prompt-prefix drift rather than genuine context changes.

## Recommended action

Update Claude Code and re-run one representative gateway-backed session plus one plugin-heavy workflow before changing fleet-wide pins:

```bash
claude update
claude --version
```

If you use a proxy or gateway, confirm authentication with the same environment and credentials your CI runners use. If you maintain plugins, test the parent-directory loading behavior in a disposable workspace before adopting it in shared automation.
