Claude Code **v2.1.271** gives teams more precise controls around automated plugin installation, subagent context, sandboxed network access, and self-hosted runners. It also brings fast mode to Remote sessions, improves fullscreen configuration, and closes several policy, permission, and session-resume gaps. **v2.1.272**, released on 15 September, contains only the upstream note “Bug fixes and reliability improvements,” so there is no separate user action to explain from that release.

## The useful changes

- **Plugin automation can approve one reviewed command.** `claude plugin install` and `claude plugin update` now accept `--accept-command <sha256>`. A prior `--json` run reports the marketplace-declared command in `shownCommand`, including its digest. Passing that digest accepts only the same command for the same plugin and marketplace state. If any of those inputs change, Claude Code refuses the digest and displays the command again.
- **Subagents can start without ordinary CLAUDE.md files.** Set `omitClaudeMd: true` in custom-agent frontmatter or `--agents` JSON when the delegation prompt already contains everything the subagent needs. User, project, and local `CLAUDE.md` files are omitted, while managed policy files still load. This can reduce irrelevant context, but it also removes project guidance that may be essential to the task.
- **Auto mode can narrow network access per command.** For Bash, PowerShell, and Monitor tool calls running in auto mode with sandboxing, `allowed_domains` can scope the hosts opened for that command. Other hosts remain blocked. This is a runtime safety boundary described by the release notes, not a reason to give broad permanent network access.
- **Remote sessions inherit fast-mode intent.** Cloud and self-hosted Remote sessions can now use the host's fast-mode setting or `/fast`, subject to the organization allowing fast mode.

## Safer plugin automation

The digest flow is the most immediately actionable change for CI and fleet tooling. Previously, a non-interactive install or update that encountered a marketplace-declared command needed `-y`, which accepted the command after Claude Code printed it. The new flow supports a review boundary:

```bash
claude plugin install formatter@team-marketplace --json
# Review the shownCommand object and its command text.
claude plugin install formatter@team-marketplace --accept-command <sha256>
```

The digest is intentionally narrow. It does not permanently trust the marketplace, and it does not transfer to a changed command or catalog. A person or trusted review system should still inspect the displayed command before the second invocation. This improves approval precision; it does not make an untrusted plugin safe to execute.

## Focused subagents, with an explicit trade-off

Claude Code normally loads the same user, project, and local `CLAUDE.md` hierarchy into custom subagents. That helps preserve repository conventions, but it can be wasteful or distracting for a tightly scoped agent that receives a complete delegation prompt.

With v2.1.271, an agent definition can opt out:

```yaml
---
name: dependency-reader
description: Inspect one dependency and return version evidence
tools: Read, Grep, Glob
omitClaudeMd: true
---
```

Use this only when the prompt restates every rule the subagent must follow. If the task depends on repository-specific exclusions, security rules, validation commands, or ownership boundaries, keeping the normal project instructions is usually the safer choice. The setting is ignored when the agent definition is used as the main session agent through `--agent` or the `agent` setting.

## Self-hosted and enterprise details

Operators get two runner controls worth recording. `--drain-marker-file <path>` lets the host mark a graceful, operator-initiated drain before sending `SIGTERM`; Anthropic documents the distinction as telemetry only. The marker should live somewhere sessions cannot write. `--host-config-snapshot disk|memory` controls how the runner seeds settings, skills, plugins, and MCP configuration into sessions. Disk mode verifies copied files against in-memory digests, while memory mode is capped at 64 MiB.

The release also fixes organization-policy refresh after account, organization, or API-key changes; keeps exclusive MCP control when `managed-mcp.json` is unreadable; repairs several Bash path-permission bypasses; and prevents background commands from being started a second time after conversation compaction. Teams that depend on managed policy, sandbox boundaries, or long-running unattended work should prioritize the update even if they do not use the new flags.

## What to do

Update to v2.1.272 so the v2.1.271 features arrive with the latest reliability follow-up:

```bash
claude update
claude --version
```

Then choose the controls that match your workflow. Use digest-bound plugin approval for reviewed automation, add `omitClaudeMd` only to self-contained subagents, and keep permanent sandbox allowlists narrow even when auto mode can open a host for one command.
