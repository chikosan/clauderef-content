Claude Code **v2.1.323** introduces an experimental tool-calling option and plugin compatibility checks, alongside a substantial set of reliability and security fixes. The [official release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.323) are especially relevant to teams using Bash permissions, sandboxing, plugins, or background sessions across multiple accounts.

## Code Mode is experimental and opt-in

Code Mode allows Claude to write JavaScript to call its tools. Anthropic describes it as experimental and opt-in, and says organizations can turn it off. That makes it a candidate for a controlled evaluation rather than an assumption to build into an existing workflow. The documentation URL linked from the release notes returned 404 during this editorial check, so the setup steps and operational details need verification before readers can rely on them.

For an evaluation, start with a small repository and tasks whose expected results are easy to inspect. Compare the tool activity and final changes with your normal workflow, and review the same permission prompts and output that you would otherwise. The release notes alone do not establish performance gains or describe every security boundary.

## Plugins can declare compatibility

Plugin authors can now add `engines["claude-code"]` to `plugin.json`. Claude Code does not install, update, or load plugins outside the declared version range; installation and updates select the newest version that fits. This gives maintainers a way to signal an actual compatibility boundary when a plugin relies on a newer API or cannot run on a later release.

The release also adds TypeScript hook-module checking to `claude plugin validate`. Findings are warnings by default, while `--strict` makes them fail validation. Authors should test their declared range against the versions they intend to support and run validation in their release process. A successful validation is useful feedback, but it does not replace testing the plugin's behavior in a real session.

## Recheck permissions and sandbox settings

Several fixes address cases where Claude Code did not apply the intended restriction. Anthropic lists fixes for Bash deny and ask rules missing some commands wrapped by `sudo`, `env`, and similar programs; an excluded sandbox command allowing an unnamed command outside the sandbox in some circumstances; and Write or Edit writing to a path covered by a Read deny rule. Another fix addresses a case where the Bash sandbox could switch off during a session.

For `claude -p` and Agent SDK sessions, invalid settings intended to enable the sandbox now stop startup and identify the invalid setting, rather than allowing Bash to run unsandboxed. The release also changes unavailable auto permission mode to start in Manual mode, which asks first. These are reasons to update and retest representative policy cases in a safe environment, especially if automation relies on settings supplied at startup. Do not treat a single successful test as proof that every rule or command combination is covered.

## Background sessions and account boundaries

The release fixes cases where a background session could move to a different sign-in. For example, when a named Anthropic profile is missing, changed, or overridden, the session now stops and reports the problem instead. Sessions using an API key, auth token, or workload identity from their shell also stop rather than moving to another sign-in in the stated cases.

This matters when different accounts carry different access or billing arrangements. After updating, check which profile and credentials a representative background workflow uses, and investigate any new stop message before restarting it. The notes also say that a session open during the update should be reopened for one named-profile fix.

## A practical upgrade check

Upgrade a canary installation, confirm its version, and exercise a representative plugin, background session, and sandbox policy before rolling out more broadly:

```bash
claude update
claude --version
```
