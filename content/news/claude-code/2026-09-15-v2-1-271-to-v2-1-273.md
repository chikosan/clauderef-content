Claude Code **v2.1.271** introduced more precise controls around plugin automation, subagent context, sandboxed network access, and self-hosted runners. **v2.1.272**, released on 15 September, contains only the upstream note “Bug fixes and reliability improvements.” **v2.1.273**, also released on 15 September, is the more consequential follow-up: it improves gateway observability, Remote Control handoff, managed-policy enforcement, authentication diagnostics, context accounting, scheduled-task isolation, and several permission boundaries.

## What changed in v2.1.271

- **Plugin automation can approve one reviewed command.** `claude plugin install` and `claude plugin update` can accept a reviewed command by SHA-256 instead of broadly approving whatever command a marketplace entry presents.
- **Subagents can omit ordinary CLAUDE.md files.** `omitClaudeMd: true` lets tightly scoped custom agents skip user, project, and local CLAUDE.md context while managed policy still loads.
- **Auto mode can narrow network access per command.** Sandboxed Bash, PowerShell, and Monitor calls can receive per-command `allowed_domains` instead of relying only on broader allowlists.
- **Remote sessions can use fast mode.** Cloud and self-hosted Remote sessions can follow the host fast-mode setting or `/fast`, subject to plan and organization policy.
- **Self-hosted runners gained clearer drain and config controls.** v2.1.271 added explicit controls for operator-initiated draining and host configuration snapshots.

These are useful controls for CI and fleet automation because they reduce the amount of trust that must be granted globally. They still require review: a digest-bound plugin command is safer than blanket approval, but it does not make an untrusted plugin safe.

## v2.1.273: gateway hints and Remote Control forking

For teams running Claude Code through an LLM gateway, v2.1.273 can attach additional routing and diagnostics context to requests. Setting `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` opts in to headers describing the request class, agent type, prior tool durations, compaction, and whether context has been compacted. These headers are release-note functionality; the current CLI, Commands, and Settings reference pages do not yet expose them as a stable reference interface, so they are not being added to the cheatsheet yet.

Remote Control also gets a practical workflow improvement: a session started with `claude --remote-control` or `/remote-control` can now be forked from the Claude app, with the fork continuing as a background session on the computer that owns the original session.

## Permission and managed-policy fixes matter more than the feature list

Several v2.1.273 fixes are especially relevant to unattended or enterprise use:

- Bash commands the permission checker cannot fully analyze no longer skip a required prompt when `permissions.blockReadsOutsideWorkingDirectories` applies, and a subshell can no longer hide a dangerous `rm` in bypass mode.
- `allowManagedMcpServersOnly`, `deniedMcpServers`, and `disableClaudeAiConnectors` set through MDM or `managed-settings.json` are no longer ignored when server-managed settings are also present.
- A repository-configured memory directory outside the working-directory policy boundary is no longer loaded, recalled, indexed, or used for memory extraction.
- The release reverts the v2.1.268 behavior that denied Bash lines such as `eval` or `env -C` when they could not be fully analyzed; those commands now prompt again instead of being silently denied.

For managed environments, those changes are a stronger reason to update than the new gateway headers.

## Long-running sessions and automation are more predictable

v2.1.273 also fixes operational problems that can be difficult to diagnose in CI, agents, and long sessions:

- subagents and background agents no longer lose their final result when the final streamed reply omits token usage or a model id;
- `--output-format stream-json` no longer drops a backgrounded subagent's remaining messages and final report;
- the context meter and auto-compaction stop double-counting advisor-tool turns;
- copied `.claude/scheduled_tasks.json` files no longer cause saved scheduled tasks to run in the wrong session in a new folder or worktree;
- long-session activity handling is more responsive because hook and subagent updates no longer re-process the entire conversation every time;
- `/login`, `/upgrade`, and `/extra-usage` no longer discard earlier thinking and force an unnecessary prompt-cache rewrite.

Authentication and connectivity errors are also more specific. Bedrock, Vertex, Foundry, gateway, proxy, TLS, MCP re-authentication, GitHub SAML, IP-allow-list, and cloud-session failures now point more directly at the credential or configuration that needs attention.

## What to do

If you are on v2.1.271 or v2.1.272, move to **v2.1.273** before depending on the new automation controls in long-running or managed environments:

```bash
claude update
claude --version
```

Teams using an LLM gateway can evaluate the new hint headers separately rather than enabling them everywhere immediately. Teams using Remote Control, managed MCP policy, self-hosted runners, scheduled tasks, or background agents should prioritize the update because most of the value in v2.1.273 is reliability and policy correctness rather than a new interactive command.
