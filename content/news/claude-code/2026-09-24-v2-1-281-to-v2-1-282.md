Claude Code **v2.1.281** (September 23), **v2.1.282** (September 24), **v2.1.283** (September 25), **v2.1.284** (September 28), **v2.1.285** (September 29), **v2.1.286** (September 30), **v2.1.287** (October 1), and **v2.1.288** (October 2) are operations-focused updates. Together they add gateway and policy controls, expand MCP and plugin configuration, add a prompt-audit workflow, introduce safer plugin installation boundaries, bound retries, and fix failure modes that matter in remote, headless, scheduled, and long-running sessions.

## v2.1.288 improves review, recovery, and session safety

Claude Code v2.1.288 adds `--max-findings <n>|all` to `/code-review`, so a reviewer can request more or fewer findings than the usual limit and keep that choice until resetting it with `--max-findings default`. The same option is available through the `/review` alias. This is useful when a quick review should stay focused or a release review needs a fuller inventory, but the number of findings is not a quality guarantee.

The release also adds `$.ui.selection()` for mods, which exposes the last fullscreen text selection and the transcript row containing it when applicable. Agent view gains Ctrl+F session search, Alt+Up/Down group navigation, and configurable keybindings. A cleared prompt can be restored with Up after Ctrl+C, including pasted text and images, reducing the risk of losing a long draft.

Several fixes target long-running and unattended sessions. Non-interactive sessions and subagents can continue after a mid-response timeout when a partial response exists, long conversations compact instead of failing after a zero-token reply, and resumed sessions preserve restored files, context, thinking, and transcript state more reliably. Unattended retry watchdogs now give up after three timeouts instead of retrying for hours. The release also fixes a dangerous recursive `rm` path inside shell wrappers in bypass-permissions mode and closes additional plugin, hook, MCP, authentication, and session-recovery edge cases.

## v2.1.287 adds deeper plugin behavior and safer observability

Claude Code v2.1.287 introduces Claude Mods, which let plugins modify deeper behavior, and ships a first-party “You should know” mod that uses a side agent to flag things a user or Claude might miss. The built-in mod is enabled with `/plugin enable cc-plugin-you-should-know@builtin` for first-party sessions with telemetry enabled. Because mods can change behavior more deeply than ordinary plugin components, review their code, permissions, hooks, and data handling before enabling them.

MCP servers using the 2025-11-25 protocol can now send URL prompts for browser-based sign-in flows. If an existing server stops connecting after upgrading, its configuration may need `bareElicitationCapability: true`. OpenTelemetry `user_prompt` events also gain a `prompt_text` copy for backends that nest dotted keys; operators must apply the same masking and retention rules to it as to `prompt`.

The release adds a built-in REST-only `gh api` for Anthropic-managed Git sessions on macOS and Linux when GitHub CLI is not installed. It also adds an `n:<text>` filter to the agents view and a Windows warning when denying Bash also removes the only available PowerShell shell. Among the fixes are safer dangerous-`rm` handling when output redirection is present, more reliable Remote Control reconnects, and a correction for repeated `asyncRewake` notifications from missing hook scripts.

## v2.1.286 makes unattended and plugin-heavy workflows safer

Claude Code v2.1.286 changes `--bare` so it connects only the MCP servers named on the command line, sends no system reminders to the model, and starts no background tasks. A shell command that reaches its timeout now stops instead of moving into the background under this mode. That makes `--bare` a clearer fit for tightly controlled automation, but scripts should still name the MCP configuration they actually need and test timeout handling.

Plugin installation now refuses npm sources that are Git repositories or local folders, and plugin dependencies are installed only from registry packages. This narrows the supply-chain surface for plugin installs and makes a previously implicit assumption explicit: a plugin's npm dependencies must resolve as packages from a registry. Plugin authors should check their manifests and installation instructions before upgrading.

The release also changes failed API retries so one limit covers a whole model call, with the default retry settings sending at most 14 requests. Model refusal and `--fallback-model` retries run at standard speed when a fast fallback cannot run fast, and the user is told once in an interactive session. These are operationally useful changes for headless jobs and gateway operators because retry behavior is bounded more clearly, while still requiring monitoring for provider errors and spend.

Several fixes address authentication, sessions, and data handling: expired gateway credentials no longer open duplicate login browsers across processes, `claude auth status` now identifies a stored Console API key as `api_key`, and Remote Control messages and attachments are less likely to be falsely marked delivered or abandoned. Secret masking also covers more URL-password and percent-encoded Bearer-token cases, and `/feedback` exports remain valid JSONL after redaction.

For interactive users, fullscreen list navigation gains mouse support, the permission prompt can show a count when several requests are stacked, and VS Code adds bookmarks, question/answer rows, previews, and links to related session artifacts. Those improvements are useful quality-of-life changes, but the release's most important upgrade path is still the safer behavior around automation, plugins, credentials, and redaction.

## v2.1.285 adds provider policy and plugin configuration

Claude Code v2.1.285 adds `allowedProviders` as a managed setting. Administrators can use it to limit a machine to selected API providers, including the Anthropic API, custom endpoints, Bedrock, Vertex AI, Foundry, Claude Platform on AWS, Mantle, or a cloud gateway. This makes provider choice an explicit fleet policy rather than a setting each developer can change independently.

The release also adds `claude --desktop`, which opens the current directory in the Claude desktop app or resumes a session there with `--continue` or `--resume <id>`. Plugin operators get `claude plugin configure <plugin>` to inspect unset options or save values from standard input. `claude plugin install --config` can now set a bundled `.mcpb` server's own `<server>.<key>=<value>` settings at install time, so a plugin can start configured without a separate visit to the Configure screen.

For restricted environments, `CLAUDE_CODE_DISABLE_WEB_FETCH=1` disables the WebFetch tool. `CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES` caps re-sends after a non-streaming fallback timeout. The release also makes several cloud, MCP, plugin, sandbox, authentication, and session-recovery paths more predictable, including retrying transient Remote Control file downloads and avoiding repeated fallback retries after content-filter or streaming failures.

## v2.1.284 adds a model update and useful recovery controls

Claude Code v2.1.284 adds Claude Sonnet 5.5 (`claude-sonnet-5-5`) to the Anthropic API and makes it the default Sonnet model there. The release notes describe a 1M-token context window, $2/$10 per million input/output tokens, and $0.20 per million cache reads. Treat those figures as provider pricing and availability details, not as a promise that every Claude Code plan or gateway exposes the model immediately.

The interactive terminal gains `/mcp reconnect all`, which retries every MCP server that failed to connect or needs authentication. That is a more useful recovery path than restarting a session when several servers are temporarily unavailable. A new `/rate-limit-options` command is also listed in `/help` and the command menu for claude.ai subscribers, giving usage-limit notices a discoverable destination.

The `/effort` slider can now be rebound through `keybindings.json` with `effortSlider:decreaseEffort`, `effortSlider:increaseEffort`, and `effortSlider:toggleUltracode`. The release also changes Ultracode into an independent toggle, so it no longer forces the xhigh effort level. Gateway operators get clearer startup warnings for incomplete managed model policies, plus Google Cloud OTLP authentication and `private_key_jwt` identity-provider support.

The fixes are broad, but several have a clear operational payoff: resumed MCP calls wait briefly for a still-connecting server, repeated usage-limit requests back off, malformed Agent SDK image input is handled without poisoning later turns, and prompt compaction can run one more time when the shortened request is still too large. Plugin permission pre-approval, Foundry resource validation, workspace trust, recursive deletion safeguards, and sandbox startup also receive targeted fixes.

## v2.1.283 adds model policy and prompt auditing

v2.1.283 adds `availableModelsMatch` and `deniedModels` to managed settings. With `availableModelsMatch: "exact"`, an `availableModels` entry permits only the named model version, so a newly released model stays blocked until an administrator lists it. `deniedModels` adds an explicit block list even when `availableModels` would otherwise allow a model. Together, these controls help teams make model rollout an intentional policy change instead of an accidental side effect of an upstream release.

The release also adds `/doctor prompt-audit` (with `/checkup prompt-audit` as an alias). It audits `CLAUDE.md` files, skills, agents, and commands for prompting patterns written for older models. The related `prompt-audit` skill is also documented for API projects, but it is a different entry point: use the doctor command to inspect Claude Code configuration and the skill when auditing prompts and tool descriptions in an application.

For gateway operators, `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` opts into an `x-claude-code-prompt-id` hint header so a gateway can group requests belonging to one user prompt. OpenTelemetry can also include MCP, WebFetch, and WebSearch output in the `tool.output` span event when `OTEL_LOG_TOOL_CONTENT=1`; because that can expose sensitive tool output, enable it only with an appropriate redaction and retention policy.

The rest of v2.1.283 is a broad reliability and compatibility pass: SDK sessions preserve deferred tool calls and usage more consistently, background MCP progress remains visible, stdio servers shut down more cleanly, plugin validation catches unsafe or missing paths, and managed sandbox settings fail closed when nested configuration is invalid. The release also includes a Windows safeguard for recursive deletion commands and fixes session, model-picker, vim-mode, VS Code, and Remote Control edge cases.

## v2.1.282 makes terminal output easier to control

v2.1.282 adds `maxProseWidth`, a setting that caps the width of Claude's prose in wide terminals while leaving tables and code blocks at full width. It also adds startup, `/status`, and `claude doctor` reporting for telemetry variables in project settings that were ignored or disabled telemetry. The managed `allowClaudeInChromeWithManagedMcp` setting now lets `claude --chrome` run alongside an exclusive `managed-mcp.json`, with a more specific error when policy still blocks it.

The release also changes auto mode to use the server-side classifier by default for direct Anthropic API connections when telemetry is off; `CLAUDE_CODE_AUTO_MODE_SERVER=0` opts out. Managed and project settings now apply tighter boundaries to sandbox exclusions and OpenTelemetry variables, and skill, command, and MCP namespaces that could be confused with claude.ai-synced content are handled more narrowly.

## Gateway controls get more enterprise-friendly

The most notable additions are in the Claude apps gateway. Bedrock upstreams can now use `assume_role`, so the gateway can call Amazon Bedrock through an STS-assumed IAM role, including a role in another AWS account. The release also adds `guardrail: {id, version}` for Bedrock upstreams, allowing an Amazon Bedrock guardrail to be applied to every request routed through those upstreams.

For observability, gateway configuration gains `telemetry.resource_attributes`, which lets operators attach fixed labels to telemetry emitted for Claude Desktop and `/login` sessions. The release also adds support for newer Claude Desktop policy keys in `desktop` policy blocks, including `blockReadsOutsideWorkingDirectories` and `disableBypassPermissionsMode`.

These additions are particularly useful for organizations that already treat the gateway as a policy and identity boundary. They make it easier to separate runtime identity from the gateway host itself and to add stable fleet or environment labels to telemetry.

## MCP and plugin validation improve

v2.1.281 adds MCP URL-mode elicitation for connections using the 2026-07-28 protocol. An MCP server can now ask Claude Code to open a browser-based flow, without leaving a waiting dialog behind when the server has no way to confirm completion.

`claude plugin validate` also gains MCP-specific checks. It can now flag `.mcp.json` entries that would otherwise be silently dropped, undeclared `${user_config.*}` references, and insecure URLs. This is useful as a pre-merge or CI check for plugin repositories because configuration problems can be caught before users discover that a server never loaded.

The release also adds an auto-mode recommendation to `/insights`, estimating how many recent permission prompts auto mode could have handled. That is an advisory signal rather than a new permission mode, but it can help teams evaluate whether auto mode would meaningfully reduce interruption in their current workflow.

## Long-running and unattended sessions get safer

A large part of v2.1.281 is reliability work around persisted sessions, proxies, and automation. Claude Code now repairs more resume-history inconsistencies instead of repeatedly losing prior reasoning, preserves more large-session context, and avoids retry loops that could ignore `--max-turns` when tool-call parsing and output truncation alternated.

Proxy and gateway handling also gets several fixes: truncated streams are less likely to be treated as complete responses, duplicated stream events no longer cause tool calls to run twice, partial responses can survive a dropped event, and trailing usage frames no longer erase the stop reason. Retry-watchdog and fast-mode behavior are also more conservative around rate limits and `Retry-After` handling.

For headless and scheduled workloads, the release fixes `stream-json` sessions that could fail after plain-string assistant history, host-side MCP handshakes that could stall the first message indefinitely, scheduled `/loop` wakeups that could fire every second after delivery failure, and spawned sessions that previously lost the parent `--setting-sources` restriction.

## Permission boundaries tighten

There are several security-relevant fixes as well. In auto mode and `--dangerously-skip-permissions`, a recursive `rm` whose target comes only from command substitution now requires confirmation even when a Bash allow rule exists, unless the explicit compatibility override is set. Permission rules containing a NUL byte now match nothing instead of expanding into a wildcard, and workspace trust is enforced before `claude --bg` starts a background session or runs project hooks.

The release also avoids reading special macOS resolution paths such as `/.vol`, `/.nofollow`, and `/.resolve` before approval, and improves handling of null bytes in file paths so the individual tool call fails cleanly instead of terminating the whole turn.

## The cheatsheet gains the documented audit command

The coordinated reference pass checked the official documentation index, settings reference, CLI and command references, managed settings, monitoring, plugin, MCP, hooks, skills, memory, subagent, sandbox, and authentication pages. The compact reference now records `/doctor prompt-audit`, the documented `OTEL_LOG_TOOL_CONTENT` opt-in, and the managed model-policy keys. Release-only details such as `maxProseWidth`, the managed Chrome setting, and the gateway hint header remain in this article because they were not yet covered by the compact reference pages used for the cheatsheet.

## What to do

If you run Claude Code behind the Claude apps gateway, on Bedrock, with MCP servers, or in scheduled/headless automation, v2.1.281–v2.1.288 are worth validating promptly. Test role assumption, guardrail application, model allow/deny policy, prompt auditing, MCP startup and URL-based re-authentication, plugin and mod validation, resume behavior, terminal width, model availability, retry behavior, review-finding limits, and your permission rules before broad rollout.

```bash
claude update
claude --version
```

The cheatsheet update is limited to interfaces independently documented in the current Commands, Managed Settings, and Monitoring references; it does not treat release-note-only fields as stable compact-reference entries.
