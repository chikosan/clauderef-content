Claude Code **v2.1.319** הוא שחרור משמעותי לשיפור אמינות ושליטה. השינוי המרכזי הוא תמיכה במשימות MCP במפגשי טרמינל: פעולה ארוכת‑ריצה של MCP יכולה לעבור מיד לרקע, בעוד ש-Claude יידע כשהתוצאה מוכנה. השחרור גם עושה את התנהגות מצב‑האוטו ליותר מפורשת כאשר טלמטריה או דגלי תכונות אינם זמינים, מוסיף הגדרה שמונעת פעולות במקום להמתין לאישור, ומשפר אותות כישלון לאוטומציה ללא השגחה.

## עבודת MCP יכולה לצאת מהתור הקדמי

שרתים של MCP יכולים לחשוף קריאת כלי כמשימה. ב‑v2.1.319, Claude Code מעביר את אותה משימה מיד לרקע ומודיע ל‑Claude כשמסתיימת. זה נותן לאינטגרציות דרך נקייה יותר לטפל בעבודה שלוקחת יותר זמן מקריאת כלי רגילה מבלי לחסום את כל סיבוב הטרמינל.

ההתנהגות היא עם אפשרות ביטול. קבעו את `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` כאשר עטיפה או אינטגרציה צריכות ש‑Claude Code יחכה בתוך קריאת הכלי במקום. השחרור גם מציין שמשימות MCP עובדות במפגשי טרמינל ללא שליפת דגלי תכונות, כולל Bedrock, Vertex, Foundry, שערי LLM, ו‑`DISABLE_TELEMETRY`; `CLAUDE_CODE_DISABLE_MCP_TASKS=1` מכבה את היכולת לגמרי.

הרצה ברקע לא הופכת שרת MCP לאמין בפני עצמו. עברו על יישום השרת, הרשאות, גישת רשת, וטיפול בתוצאות, וודאו שהעטיפה שלכם יכולה לקשר בין התוצאה הסופית לבין הסשן המקורי.

## מצב‑האוטו יותר מפורש מאחורי שערים

כאשר טלמטריה או דגלי תכונות כבויים, כולל מאחורי שער LLM, מצב‑האוטו כעת שואל או דוחה פעולות שהשרת לא יכול לבדוק. הוא כבר לא נופל באופן שקט לברירת המחדל של הממיין המובנה. קבעו `CLAUDE_CODE_AUTO_MODE_SERVER=0` כדי להמשיך להשתמש באותו ממיין; Bedrock, Vertex ו‑Foundry אינם משתנים על‑פי כלל הגיבוי הזה ספציפית.

מפעילי שערים יכולים להגדיר `CLAUDE_CODE_AUTO_MODE_SERVER=1` כדי לאפשר בדיקת צד‑שרת גם כאשר `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` מוגדר. אם הגדרה מנוהלת מכבה את הבטא הניסיונית, היא חייבת גם להגדיר את מתג השרת. הגדרות פרויקט ותוספים אינם יכולים עוד להפעיל בדיקת צד‑שרת לאחר שהיא הושבתה מחוץ לפרויקט.

זו שינוי מדיניות משמעותי להרצות ללא השגחה: איפוס של משמר אוֹבטחה שאינו זמין כעת נראה כהודעת בקשה או כסירוב במקום שיחליף אותו בשקט. בדקו את המצב הרצוי בכל ספק והתכוננו להתמודד עם סירוב ככישלון אמיתי באוטומציה.

## הרשאות יכולות להיכשל סגורות במקום להציג בקשה

ההגדרה החדשה `permissions.denyInsteadOfPrompting` דוחה קריאת כלי שאחרת הייתה ממתינה להודעת הרשאה, וכך מאפשרת לתור להמשיך. זה חל על מפגשי טרמינל, סאב‑אייג'נטים, וחברי צוות. זה שימושי לעבודה שאינה יכולה להשיב לשאלה אינטראקטיבית, אך זה גם אומר שהפעולה שנדחתה עלולה להשאיר את העבודה המבוקשת לא שלמה. שילבו את ההגדרה עם לוגינג מפורש ונתיב ברור לניסיון חוזר או הסלמה.

השחרור גם מתקן מספר אותות כישלון ב‑headless. פלט הטקסט וה‑JSON של `claude -p` עכשיו יוצא עם קוד יציאה 1 כאשר פעולות מצב‑האוטו נדחות כי לא זמינה בדיקת בטיחות. היעדר שרת MCP במהלך `claude -p --resume` שומר על הקריאה המושהית ויוצא בקוד 1, ומארחי Agent SDK מקבלים את שגיאת ה‑API של הריצה שנכשלה במקום הודעת קוד יציאה גנרית במקרה אחד של חוסר מקום בדיסק.

## מה לבדוק לפני שדרוג

שדרגו קודם לסביבת קנארי, ואז הריצו משימת MCP ארוכת‑ריצה אחת ואשרו שהשלמתה מגיעה ל‑Claude. החליטו האם המתנה בחזית או הרצה ברקע מתאימה לכל אינטגרציה. עבור שערים, בדקו את שני מתגי הסביבה של מצב‑האוטו עם אותן הגדרות מנוהלות המשמשות בייצור. לבסוף, גרמו לעטיפות לכשול כאשר מתבצעת יציאה בקוד 1, שגיאות API מובנות, שמירת משמר נדחית חסרה או סירוב משמירה — אל תתייחסו לצעד מצליח קודם כהוכחה שההרצה הושלמה.

```bash
claude update
claude --version
```
