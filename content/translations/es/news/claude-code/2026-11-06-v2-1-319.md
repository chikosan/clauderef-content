Claude Code **v2.1.319** es una versión importante centrada en fiabilidad y control. El cambio principal es el soporte para tareas MCP en sesiones de terminal: una operación MCP de larga duración puede moverse inmediatamente a segundo plano, mientras Claude es notificado cuando el resultado está listo. La versión también hace que el comportamiento del modo automático sea más explícito cuando la telemetría o las banderas de función no están disponibles, añade una opción que deniega acciones en lugar de esperar permisos interactivos y mejora las señales de fallo para la automatización sin cabeza.

## El trabajo MCP puede salir del primer plano del turno

Los servidores MCP pueden exponer una llamada a herramienta como una tarea. En v2.1.319, Claude Code mueve esa tarea a segundo plano de inmediato y avisa a Claude cuando se completa. Esto ofrece a las integraciones una forma más limpia de manejar trabajos que tardan más que una llamada de herramienta ordinaria sin bloquear todo el turno de terminal.

En una sesión interactiva, establezca `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1` cuando un wrapper o integración necesite que Claude Code espere el resultado de la tarea MCP dentro de la llamada a la herramienta. El backgrounding automático todavía puede mover una llamada larga a segundo plano después de dos minutos; establezca también `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS=0` cuando deba desactivar ese umbral. La versión también indica que las tareas MCP funcionan en sesiones de terminal sin obtención de feature flags, incluyendo Bedrock, Vertex, Foundry, pasarelas LLM y `DISABLE_TELEMETRY`; `CLAUDE_CODE_DISABLE_MCP_TASKS=1` desactiva por completo la capacidad.

La ejecución en segundo plano no convierte por sí misma a un servidor MCP en confiable. Revise la implementación del servidor, permisos, acceso a red y manejo de resultados, y asegúrese de que su wrapper pueda correlacionar el resultado eventual de la tarea con la sesión origen.

## El modo automático es más explícito detrás de gateways

Cuando la telemetría o las feature flags están desactivadas, incluyendo detrás de una pasarela LLM, el modo automático ahora pregunta o deniega acciones que el servidor no puede comprobar. Ya no cae silenciosamente en el clasificador incorporado. Establezca `CLAUDE_CODE_AUTO_MODE_SERVER=0` para seguir usando ese clasificador; Bedrock, Vertex y Foundry no se ven afectados por esta regla de reserva en particular.

Los operadores de gateway pueden poner `CLAUDE_CODE_AUTO_MODE_SERVER=1` para habilitar la comprobación del lado del servidor incluso cuando `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` esté activado. Si una configuración gestionada desactiva las betas experimentales, debe establecer también el conmutador del servidor. Las configuraciones de proyecto y los plugins ya no pueden volver a activar la comprobación del lado del servidor después de que haya sido deshabilitada fuera del proyecto.

Este es un cambio de política significativo para ejecuciones desatendidas: una salvaguarda no disponible ahora se hace visible como un aviso o una denegación en lugar de ser sustituida silenciosamente. Pruebe el modo previsto en cada proveedor y haga que la automatización trate una denegación como un fallo real.

## Los permisos pueden fallar en modo "cerrado" sin un aviso

La nueva opción `permissions.denyInsteadOfPrompting` deniega una llamada a herramienta que de otro modo esperaría un aviso de permiso, permitiendo que el turno continúe. Se aplica a sesiones de terminal, subagentes y compañeros de equipo. Esto es útil para trabajos que no pueden responder a una pregunta interactiva, pero también significa que una operación denegada puede dejar el trabajo solicitado incompleto. Combine la opción con registros explícitos y una vía clara de reintento o escalado.

La versión también corrige varias señales de fallo para ejecuciones sin cabeza. La salida de texto y JSON de `claude -p` ahora sale con código 1 cuando las acciones en modo automático son rechazadas porque no hay una comprobación de seguridad disponible. Un servidor MCP faltante durante `claude -p --resume` preserva la llamada diferida y sale con código 1, y los hosts de Agent SDK reciben el error API de la propia ejecución fallida en lugar de un mensaje genérico de código de salida en un caso de disco lleno.

## Qué comprobar antes de actualizar

Actualice primero un canario y luego ejecute una tarea MCP de larga duración y confirme que su finalización llega a Claude. Decida si la espera en primer plano o la ejecución en segundo plano encaja con cada integración. Para pasarelas, pruebe ambos conmutadores de entorno de modo automático con las mismas configuraciones gestionadas que use en producción. Finalmente, haga que los wrappers fallen con estado de salida 1, errores API estructurados, salvaguardas rechazadas y herramientas diferidas faltantes en lugar de tratar un paso anterior exitoso como prueba de que la ejecución terminó.

```bash
claude update
claude --version
```
